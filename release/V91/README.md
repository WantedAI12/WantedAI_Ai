- 따라서 Git clone만으로 개인 배포의 전체 자료와 체크포인트를 얻는 것은 아닙니다. 실제 운영 묶음은 별도로 해시 검증된 설정이 필요합니다.

## 검증을 구분해서 읽기

1. V91 설치 패키지: 관련 로컬 테스트 **278개 통과**.
2. 실제 배포 이미지: API **26건 기대 결과 일치**(200 25건, 의도된 빈 증거 422 1건). 배포 응답의 실제 백엔드 Java DTO 파싱 **15건 성공**.
3. 큰 로션 요청 추가 확인: **281.6316초**, 원 JSON 23,322,844바이트 → 전송 JSON 6,186,523바이트, 추가 Java 파싱 및 무손실 복원 성공. 실제 점수 **85.788375**, 목표 미달 판정 유지.
4. 공개용 소스 작업트리: V91 관련 계약 테스트 **154개 통과**, 기존 CI의 정적 검사 명령 통과, 런타임 214모듈 AST 일치 확인.
5. **기존 광범위 품질 테스트는 모두 통과한 상태가 아닙니다.** 로컬에서 `tests/test_recommender.py::test_green_aquatic_forest_brief_exceeds_threshold`가 실패했습니다. 기대값 `prototype_ready`에 대해 현재 배포본과 동일한 소스가 `no_safe_match`를 반환합니다. 이 실패를 지우거나 90점으로 바꾸지 않았습니다. 해당 테스트는 CI에도 그대로 남겨 두었습니다. 광범위 로컬 실행은 실패를 별도 재현한 후 중단했으며 완료로 기록하지 않습니다.

GitHub Actions의 결과는 각 실행에서 별도로 확인해야 합니다. 위 로컬·배포 기록을 이번 PR의 전체 CI 성공으로 표시하지 않습니다. 기존 코드 리뷰 규칙과 실제 배포본 대조를 이용해 공개 범위를 선정했습니다.

후속 확인에서 위 그린·아쿠아틱 실패는 새 장면 해석과 소형 카탈로그 범위가 맞지 않는 과거 기대값으로 확인됐습니다. 현재 배포의 후보 반환 및 탐색 함수 계약도 함께 대조해 [CI 정합성 수정](CI_REPAIR.md)에 원인과 보존한 검사 조건을 기록했습니다. 전체 재실행의 성공 여부와는 구분합니다.
